## Start on Opus 5.5. Turn effort down before you switch.

This page used to say "Sonnet for doing, Opus for deciding." The Claude 5.5 models changed the math. Anthropic's models page now says to "start with Claude Opus 5.5 for most workloads," and its Opus 5.5 guide reports that at the default `medium` effort it matched or beat Opus 5 at `high` on coding tasks, in fewer steps and fewer tokens.

So the dial you reach for first is effort, not the model. If a task is simple, `/effort low` on Opus 5.5 thinks less and costs less, and Anthropic says `low` comes close to Opus 5 at `high` on several coding evaluations. Switch to Sonnet 5.5 when you need speed or you're running a lot of the same small job, since it costs half as much per token.

| | Fable 5.1 | Opus 5.5 | Sonnet 5.5 | Haiku 4.5 |
|---|---|---|---|---|
| Price per million tokens (input / output) | $10 / $50 | $4 / $20 | $2 / $10 | $1 / $5 |
| Default effort | `high` | `medium` | `high` | none |
| Context window | 1M | 1M | 1M | 200K |
| Speed | Slower | Moderate | Fast | Fastest |

From Anthropic's [models overview](https://platform.claude.com/docs/en/about-claude/models/overview), checked 4 October 2026. Opus costs 2x Sonnet ($4 / $2 = 2), and Fable costs 2.5x Opus ($10 / $4 = 2.5).

In the desktop app, the model and effort sit beside the send button, and both are clickable. Click the model name to get the list of models. Click the effort level to open a slider that runs from `low` to `max`.

In the terminal, `/model` and `/effort` do the same job.

## When to Use the Fable Class

Fable 5.1 is Anthropic's top model. Its models page says to use it "for demanding reasoning and long-horizon agentic work, or when your evals on Claude Opus 5.5 at higher effort still fall short." In plain terms: try Opus 5.5 at `high` first, and move to Fable only when that still fails. It runs extra safety classifiers, so a small share of edge-case requests come back refused. Anthropic's own page: [anthropic.com/claude/fable](https://www.anthropic.com/claude/fable).

**Pricing:** $10 / $50 per million tokens, the most expensive of the four.

## When to Use the Opus Class

Opus 5.5 is the default, and for most work it should stay that way.

- Most coding, including multi-file changes and refactors
- Debugging where your first approach already failed
- Code review: Anthropic says early testers saw more bugs caught and fewer false alarms than on Opus 5
- Reading dense charts, diagrams and screenshots
- Writing PRDs, analysis and strategy documents

It also writes output more than 30% faster than Opus 5, per Anthropic's guide, so the old "Opus is slow" complaint mostly went away. Reserve `xhigh` and `max` for work where you've seen them help; Anthropic says the same.

**Pricing:** $4 / $20 per million tokens.

## When to Use the Sonnet Class

Use Sonnet 5.5 when speed matters or the job repeats many times.

- Quick edits where you'll read the result straight away
- Bulk work: renaming across files, formatting, generating many similar things
- Background agents doing mechanical work
- Chat-style back and forth, where a fast first word matters

Two things to know. Sonnet 5.5's guide says it tends to add tests and docs nobody asked for, and that at `low` and `medium` effort it's more likely to stop and check in before a long task is finished. If either bothers you, raise effort or add a scope line (see [prompting](/docs/foundations/prompting)). For the hardest long-horizon work, Anthropic itself says an Opus model is the better choice.

**Pricing:** $2 / $10 per million tokens, half of Opus.

## When to Use the Haiku Class

Haiku is for volume work where you don't need deep reasoning. Think of it like the intern who types really fast.

- Quick code formatting
- Simple lookups ("what does this function do?")
- Running through checklists
- Basic text transformations
- Syntax checks

The real use case is sub-agents. When you're running background code review or spinning up a test-execution agent, Haiku is fast and cheap enough that you can run several in parallel without watching your bill climb.

**Pricing:** $1 / $5 per million tokens, the cheapest. Check before you build on it: Anthropic lists Haiku 4.5's retirement as "not sooner than October 15, 2026," and its knowledge cutoff is February 2025, much older than the 5.x models.

## How Claude Code Picks For You

On **Claude Pro** ($20/month), **Max**, **Team** and **Enterprise**, Claude Code now defaults to Opus 5.5 at `medium` effort. Before v2.1.280, Pro started on Sonnet. `/model sonnet` now picks Sonnet 5.5, the default Sonnet since Claude Code v2.1.284.

On **Claude Max** (from $100/month) you get 5x or 20x the usage of Pro. Get here when you're hitting Pro limits daily, not before.

On the **API** (pay per use) you pick the model per request. Full control, full responsibility for the bill.

### Switching Models Mid-Session

In the app, use the picker beside the send button, as in the session above. In the terminal, type:

```bash
/effort low     # Same model, less thinking, lower cost
/model sonnet   # Faster and half the price, for bulk work
/model haiku    # Cheapest, for simple background jobs
/model opus     # Back to the default
```

You can do this mid-conversation, mid-task. The context carries over. One cost to know: Anthropic's docs say changing effort between requests invalidates the prompt cache, so set it at the start of a session where you can.

## Which Plan Should I Get?

If you're just trying it out: start free, see if you like it.

If you're using it regularly: Pro at $20/month handles most people's actual usage. Start here and upgrade only when you start hitting limits and it frustrates you. You'll know.

If you're a power user building things all day: Max from $100/month gives you the headroom, with 5x the usage of Pro, or 20x on the higher tier. Pro already includes Opus, so you're paying for the extra usage, not model access.

If you're building apps that call Claude: API, pay per token, pick your model per call.

## The Decision in One Line

Opus 5.5 by default, effort as the cost dial, Sonnet 5.5 for speed and volume, Fable when Opus at `high` still falls short.

Start there and adjust based on what you actually see, not what you imagine might be better.

## Pro Tips

1. **Lower effort before you lower the model.** `/effort low` on Opus 5.5 keeps the stronger model and cuts thinking. Drop to Sonnet when you need speed.
2. **Use Sonnet or Haiku for mechanical sub-agents.** Test runs and lookups in the background don't need Opus-level reasoning. Keep code review on Opus.
3. **Watch your context window.** The 1M token limit sounds massive, but loading whole codebases repeatedly adds up. Use `/compact` to trim.
4. **You pay for thinking.** Thinking tokens bill as output, even when Claude Code collapses them on screen. Effort is the dial: `/effort low` on Opus 5.5 thinks less and costs less. See [thinking modes](/docs/patterns/thinking-modes).
