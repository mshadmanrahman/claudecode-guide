## Sonnet for doing. Opus for deciding.

Here's the whole rule. If your prompt is an instruction ("do this", "fetch that", "rename these", "write the test for this function"), use Sonnet. You already know what you want, and you need it carried out quickly and cheaply. If your prompt is a question with no obvious answer ("how should we structure this?", "why does this keep failing?", "which of these approaches is right?"), use Opus. You're paying for judgment, and a wrong call costs more than the tokens.

One catch: Claude Code now starts you on Opus 5.5. That's a good default for deciding work and an expensive one for everything else. So when you sit down to execute a plan, switch with `/model sonnet`.

There are four model classes, they're meaningfully different, and picking wrong costs you either money or quality.

## When to Use the Fable Class

Fable 5.1 sits above Opus in Anthropic's lineup, in what they call the Mythos class. Reach for it on the hardest long-horizon work: a multi-hour agentic run, a refactor across a codebase you don't fully understand, a problem where Opus has already stalled twice. For everyday coding it is overkill, and it ships with extra safety measures on dual-use tasks, so a small share of edge-case requests come back refused. Anthropic's own page: [anthropic.com/claude/fable](https://www.anthropic.com/claude/fable).

**Pricing:** Most expensive of the four. See [anthropic.com/pricing](https://anthropic.com/pricing) for current rates.

## When to Use the Opus Class

Use Opus when the work is a decision, and getting it wrong the first time is expensive.

- Designing system architecture or making foundational decisions
- Refactoring that touches 10+ files
- Debugging cross-file issues where your first approach already failed
- Writing PRDs, competitive analysis, strategy documents
- Security reviews and code audits where you need to be thorough

Opus generates noticeably slower than Sonnet. You feel it. For a quick bug fix it's irritating. For a 2-hour architecture session it's worth every second of waiting.

**Pricing:** Second most expensive of the four. See [anthropic.com/pricing](https://anthropic.com/pricing) for current rates.

## When to Use the Sonnet Class

Use Sonnet when the work is execution. You've already decided what should happen, and Claude just needs to do it.

- Single-file edits and bug fixes
- Writing tests, docs, code reviews
- CSS tweaks and UI changes
- Git operations and daily workflow
- Features that are mostly straightforward
- Answering questions about your codebase

Here's the thing most people discover after a week: on execution work, the quality gap between Sonnet and Opus is small, and Sonnet costs half as much per token. Once the decision is made, Opus's extra reasoning has nothing left to decide.

**Pricing:** Mid-tier. Fast enough that it never feels slow. See [anthropic.com/pricing](https://anthropic.com/pricing) for current rates.

## When to Use the Haiku Class

Haiku is for volume work where you don't need deep reasoning. Think of it like the intern who types really fast.

- Quick code formatting
- Simple lookups ("what does this function do?")
- Running through checklists
- Basic text transformations
- Syntax checks

The real use case is sub-agents. When you're running background code review or spinning up a test-execution agent, Haiku is fast and cheap enough that you can run several in parallel without watching your bill climb.

**Pricing:** Cheapest of the four by a wide margin. See [anthropic.com/pricing](https://anthropic.com/pricing) for current rates.

## How Claude Code Picks For You

On **Claude Pro** ($20/month), **Max**, **Team** and **Enterprise**, Claude Code now defaults to Opus 5.5 at `medium` effort. Before v2.1.280, Pro started on Sonnet. So for execution work, switch with `/model sonnet`.

On **Claude Max** (from $100/month) you get 5x or 20x the usage of Pro. Get here when you're hitting Pro limits daily, not before.

On the **API** (pay per use) you pick the model per request. Full control, full responsibility for the bill.

### Switching Models Mid-Session

```bash
/model opus     # Switch to Opus for a complex task
/model sonnet   # Switch back for regular work
/model haiku    # Switch to Haiku for quick tasks
```

You can do this mid-conversation, mid-task. The context carries over. Switch to Opus when you hit something hard, switch back when it's done.

## Which Plan Should I Get?

If you're just trying it out: start free, see if you like it.

If you're using it regularly: Pro at $20/month handles most people's actual usage. Start here and upgrade only when you start hitting limits and it frustrates you. You'll know.

If you're a power user building things all day: Max from $100/month gives you the headroom, with 5x the usage of Pro, or 20x on the higher tier. Pro already includes Opus, so you're paying for the extra usage, not model access.

If you're building apps that call Claude: API, pay per token, pick your model per call.

## The Decision in One Line

Opus for decisions, Sonnet for execution, Haiku for background agents and volume work.

Start there and adjust based on what you actually experience, not what you imagine might be better.

## Pro Tips

1. **Decide on Opus, then build on Sonnet.** Plan the change with Opus, then `/model sonnet` and let it carry out the plan. The context carries over.
2. **Use Haiku for sub-agents.** Code review and test agents running in the background don't need Opus-level reasoning.
3. **Watch your context window.** The 1M token limit sounds massive, but loading whole codebases repeatedly adds up. Use `/compact` to trim.
4. **You pay for thinking.** Thinking tokens bill as output, even when Claude Code collapses them on screen. Effort is the dial: `/effort low` on Opus 5.5 thinks less and costs less. See [thinking modes](/docs/patterns/thinking-modes).
